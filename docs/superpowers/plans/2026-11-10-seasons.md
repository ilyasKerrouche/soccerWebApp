# Stagioni — Piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** L'app ragiona per stagioni (anno solare, ottobre–dicembre 2025 dentro il 2026) con un selettore condiviso tra Statistiche, Giocatori e Partite, opzione "Sempre", Home sempre sulla stagione in corso.

**Architecture:** Un modulo puro `lib/season.ts` decide a quale stagione appartiene una data, quale è quella in corso e come leggere/scrivere il parametro `?stagione=` nell'URL. Le query accettano un `season: SeasonKey` e filtrano in memoria per data (i dati sono pochi). La scelta viaggia nell'URL: niente parametro = stagione in corso, quindi riaprendo l'app (che parte da `/`) si riparte sempre dalla stagione in corso; la barra in basso e i link ai giocatori portano con sé il parametro.

**Tech Stack:** Next.js 14 App Router (server component + client component), Supabase, Tailwind, test con `node --test` sui moduli in `lib/`.

**Spec:** `docs/superpowers/specs/2026-11-10-seasons-design.md`

## Global Constraints

- Stagione = anno solare; tutto ciò che è prima del 2026 conta come **2026**. Prima stagione: 2026.
- Nome stagione = l'anno ("2026"), mai "2025/26". Nessun anno scritto a mano nel codice.
- Parametro URL: `stagione`, valori `2026`, `2027`, … oppure `sempre`. Assente o non valido = stagione in corso.
- Anno della stagione in corso calcolato in ora di Roma (`Europe/Rome`).
- Testo stato vuoto: `Stagione {anno} al via: ancora nessuna partita`.
- Testo giocatore senza partite: `Nessuna partita in questa stagione`.
- Selettore: bottone a pillola nello slot `aside` di `PageHeader`, etichetta `"{anno} ▾"` o `"Sempre ▾"`; menu con la stagione in corso in cima marcata `in corso`, poi le precedenti dalla più recente, ultima voce `Sempre`. Colori da `C` in `components/ui.tsx` (menu `C.surf2`, voce attiva `C.acc`).
- Home: nessun selettore; il blocco ultima partita (campo, card, LED, "Marcatori ultima partita", "Il tuo riepilogo") usa la stagione **di quella partita**; Risultati e Classifica usano la stagione in corso.
- Nelle pagine (Task 4–7) le letture per stagione passano dalle versioni `cached*` di `lib/queries/cached.ts` (Task 2), non dalle `get*` dirette; `getPlayerProfile` e le partite restano dirette.
- `next dev`, `next build` e `npx tsc` li lancia l'utente: chiedere a lui di eseguirli. `npm test` si può lanciare.

## Review Focus

- **Partita del 31 dicembre / 1° gennaio:** `played_at` è una data `YYYY-MM-DD`; la stagione si legge dalle prime 4 cifre, senza passare da `new Date` (nessuno slittamento di fuso). Test in Task 1.
- **`?stagione=` sporco** (`2019`, `abc`, `2099`, array): si torna alla stagione in corso, niente errori né pagine vuote. Test in Task 1.
- **Partita in programma a gennaio dell'anno dopo nel dettaglio partita:** le card usano la stagione in corso, non una stagione futura con tutti zero (`Math.min(seasonOf(date), currentSeason)`). Test in Task 1 (`statsSeasonFor`).
- **Gennaio con zero partite:** Statistiche, Giocatori, Home Risultati/Classifica mostrano il messaggio di stagione al via, non podio vuoto o zeri. Verifica manuale in Task 7.
- **Cambio pagina dalla barra in basso dopo aver scelto 2026:** il parametro resta anche passando dalla Home. Test di `withSeason` in Task 1, verifica manuale in Task 7.

```ts
const NOV_2026 = new Date('2026-11-10T12:00:00Z')
const JAN_2027 = new Date('2027-01-01T00:30:00+01:00') // gia' 2027 a Roma

test('ottobre-dicembre 2025 contano come 2026', () => {
  assert.equal(seasonOf('2025-10-02'), 2026)
  assert.equal(seasonOf('2025-12-31'), 2026)
  assert.equal(seasonOf('2024-05-01'), 2026)
})
test('anno solare', () => {
  assert.equal(seasonOf('2026-12-31'), 2026)
  assert.equal(seasonOf('2027-01-01'), 2027)
})
test('stagione in corso in ora di Roma', () => {
  assert.equal(currentSeason(NOV_2026), 2026)
  assert.equal(currentSeason(JAN_2027), 2027)
  assert.equal(currentSeason(new Date('2025-11-01T12:00:00Z')), 2026)
})
test('inSeason', () => {
  assert.equal(inSeason('2025-10-02', 2026), true)
  assert.equal(inSeason('2027-01-08', 2026), false)
  assert.equal(inSeason('2020-01-01', 'all'), true)
})
test('stagioni disponibili', () => {
  assert.deepEqual(availableSeasons(['2025-10-02', '2026-03-01'], JAN_2027), [2027, 2026])
  assert.deepEqual(availableSeasons([], NOV_2026), [2026])
  assert.deepEqual(availableSeasons(['2027-01-15'], NOV_2026), [2026]) // in programma: niente stagione futura
})
test('parametro URL', () => {
  assert.equal(parseSeason(undefined, NOV_2026), 2026)
  assert.equal(parseSeason('sempre', NOV_2026), 'all')
  assert.equal(parseSeason('2026', JAN_2027), 2026)
  for (const bad of ['2019', 'abc', '2099', '2026.5', ''])
    assert.equal(parseSeason(bad, NOV_2026), 2026)
  assert.equal(parseSeason(['sempre', '2026'], NOV_2026), 'all') // array: primo valore
})
test('query e link', () => {
  assert.equal(seasonQuery(2026, NOV_2026), '')
  assert.equal(seasonQuery(2026, JAN_2027), '?stagione=2026')
  assert.equal(seasonQuery('all', NOV_2026), '?stagione=sempre')
  assert.equal(withSeason('/stats', null), '/stats')
  assert.equal(withSeason('/players/abc', '2026'), '/players/abc?stagione=2026')
})
test('card del dettaglio partita mai su una stagione futura', () => {
  assert.equal(statsSeasonFor('2027-01-08', NOV_2026), 2026)
  assert.equal(statsSeasonFor('2025-12-18', JAN_2027), 2026)
})
test('etichette', () => {
  assert.equal(seasonLabel(2027), '2027')
  assert.equal(seasonLabel('all'), 'Sempre')
  assert.equal(seasonEmptyText(2027), 'Stagione 2027 al via: ancora nessuna partita')
})
```

**Interfaces:**
- Consumes: `SeasonKey`, `inSeason` (Task 1)
- Produces (il parametro ha default `'all'`, così i chiamanti non ancora toccati restano come oggi):
  - `getPlayersWithStats(season: SeasonKey = 'all'): Promise<PlayerWithStats[]>` — righe filtrate con `inSeason(match.played_at)` **prima** di calcolare gol, presenze, fiamma e forma (così forma e fiamma ripartono con la stagione). Restituisce ancora tutti i giocatori attivi, anche a zero.
  - `getPlayerProfile(id: string, season: SeasonKey = 'all')` — `matches` filtrate per stagione; `total_goals` e `total_appearances` ricalcolati dalle partite filtrate (non più da `allMp`, che includeva anche le partite in programma); portiere, record e fiamma sulle stesse partite.
  - `getGoalkeeperRanking(season: SeasonKey = 'all')` — `matches` selezionate anche con `played_at`, `matchMap` solo per quelle in stagione; con stagione numerica esclude i portieri con `appearances === 0`.
  - `getGlobalStats(season: SeasonKey = 'all')` — seleziona anche `played_at` e filtra.
  - `getMotmCounts(season: SeasonKey = 'all')` — `computeWinners` seleziona `id, played_at` delle partite chiuse e scarta quelle fuori stagione; `getMotmWinnersByMatch` e `getAllMotmWinners` invariate (passano `'all'`).
  - `getPlayedDates(): Promise<string[]>` — `played_at` di tutte le partite giocate (`is_upcoming = false`), per costruire il selettore.

  - `SEASON_DATA_TAG = 'season-data'` (in `lib/queries/cached.ts`)
  - `lib/queries/cached.ts`: versioni in cache delle letture sopra — `cachedPlayersWithStats(season)`, `cachedGoalkeeperRanking(season)`, `cachedGlobalStats(season)`, `cachedMotmCounts(season)`, `cachedPlayedDates()` — con `unstable_cache(fn, [nome], { revalidate: 60, tags: [SEASON_DATA_TAG] })`; la stagione fa parte della chiave perché è un argomento. Le pagine dei Task 4–7 usano queste.

Perché: con il selettore le pagine diventano dinamiche e perderebbero la cache di 60 secondi di oggi; così i dati restano in cache per stagione.
